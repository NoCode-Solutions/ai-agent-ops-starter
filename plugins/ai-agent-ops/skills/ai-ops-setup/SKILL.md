# 土台をつくる

ユーザーの会社の中身は、ファイルでは運べない。**聞き出してから書く。**推測で埋めない。

## 事前の確認

1. 次の場所をすべて確認し、既にあるものを一覧にしてユーザーへ見せる
   - ルートの `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md`
   - `memory/` ディレクトリ
   - 親ディレクトリの `CLAUDE.md`（上位から引き継がれている指示がないか）
2. あれば**上書きしない。**「既にあるので、足りない節を足す形にしますか」と聞き、差分を見せてから進める
3. 何も無ければ新規作成でよい

**先に伝えること。**作るファイルはリポジトリの中に置かれるので、コミットすればチームに共有される。顧客名・個人名・認証情報・社外秘の数値は書かない。書きたい場合は `CLAUDE.local.md` など共有されない場所に分ける。

## 質問（1問ずつ・まとめて投げない）

前の答えを見てから次を聞く。まとめて5問出すと、答えが浅くなる。

1. この会社（チーム）は何をしているか。**会社のサイトがあればURLを教えてほしい**
2. あなたに任せたい仕事は何か
3. 取り返しのつかない操作を3つ挙げるとしたら何か（送信・公開・削除など）
4. 直近1か月で、私にした同じ説明は何か（2回以上言ったこと）
5. 判断に迷ったとき、進めてよいか、止めて聞くべきか

### サイトのURLをもらったとき

読みに行き、**口で説明してもらう代わりに下書きを作って見せる。**ユーザーは直すだけでよくなる。

取るのは次の4つだけ。

- 事業の内容（何を、誰に）
- 扱っている商材やサービスの名前
- 主な顧客層
- **正式な社名の表記**（株式会社の位置、英字表記、略称の有無）

**サイトの文言をそのまま貼らない。**`CLAUDE.md` に入れるのは、仕事を頼むときに前提として要る数行だけ。沿革・理念・実績は入れない。会社案内にすると、毎回それを読ませることになる。

正式な社名の表記は、書類や文面でそのまま使う。ここが揺れると毎回直すことになるので、**記憶の1件目として `memory/feedback_company_name.md` に書いておく**とよい（索引への1行追加も忘れずに）。

読み取れなかった項目は勝手に埋めず、その場で聞く。サイトが無い、社内から外部へ出られない、URLを渡したくない場合は、口頭で答えてもらえばよい。**URLは必須ではない。**

### 追質問

3と4は、挙がった項目ごとに1つだけ追質問する。3は「それをやると何が起きるか」、4は「なぜそう直したいのか」。ここを聞かないと、次の工程で理由を推測して書くことになる。

**3と5は答えが出ないことがある。**その場合は空欄にせず、**安全側の既定値**を入れる。「送信・公開・削除・上書き・課金・権限変更は、実行前に必ず人へ確認する」。そのうえで「これは仮です。決まったら差し替えてください」と本文に明記し、未決であることが読んで分かる状態にする。

## 作るもの

| ファイル | 中身 |
|---|---|
| `CLAUDE.md`（ルート） | 下記6節 |
| `memory/MEMORY.md` | 1行1件の索引 |
| `memory/NOW.md` | いまの状況。**80行以内**という上限をファイル自体に書く |
| `memory/feedback_<内容>.md` | 質問4の答えを1件1ファイルで。「何をするか」「なぜか」「どう適用するか」 |

### `CLAUDE.md` の6節

1. **会社とチームのこと** … 質問1と2の答え。事業の内容、担当、任せる範囲と任せない範囲
2. **起動時に読む順番**
3. **やってはいけないこと**
4. **止まって確認する条件**
5. **完了前のチェックリスト**
6. **用語**

**3節は、行動と、やると何が起きるかを対にした表で書く。**右の列が無い表は、状況が少し変わっただけで例外扱いされる。質問3の答えをそのまま左に入れ、右に追質問で聞いた「何が起きるか」を書く。

### 記憶を読ませるための必須の記述

`memory/` に置くだけでは自動で読まれない。**`CLAUDE.md` の「起動時に読む順番」の節に、次の2行を必ず入れる。**

```
@memory/MEMORY.md
@memory/NOW.md
```

これを書き忘れると、記憶も現在地も存在するのに一度も読まれない。**このスキルでいちばん抜けやすい箇所。**

### 索引は空にしない

`memory/feedback_*.md` を1件作るたびに、`memory/MEMORY.md` へ1行追加する。

```
- [結論まで入れた見出し](feedback_<内容>.md) — ひとこと補足
```

見出しは「見積書について」ではなく「見積書の社名は正式名称で書く」のように**結論まで入れる。**ここが雑だと、必要な記憶が呼び出されない。索引が空のままだと、この仕組みは成立しない。

節の並びと表の形は `${CLAUDE_PLUGIN_ROOT}/reference/CLAUDE.md` に骨格がある。記憶に何を残し何を残さないかは `${CLAUDE_PLUGIN_ROOT}/reference/memory-writing.md`。

## 終わりに必ず出すもの

### ① 作ったものの一覧と、確かめ方

報告で終わらせず、**自分で確認してから**次の形で出す。

```
できたファイル
  CLAUDE.md            6節あり／やってはいけないこと N件（右の列あり）
  memory/MEMORY.md     索引 N行
  memory/NOW.md        N行（上限80）
  memory/feedback_*.md N件

読み込みの結線
  CLAUDE.md に @memory/MEMORY.md と @memory/NOW.md を記載済み

仮のまま残っているところ
  （空欄に既定値を入れた項目。無ければ「なし」）
```

### ② 明日からやること3行

1. いつもどおり仕事を1つ頼む。会社の説明は要らない
2. 直したくなったら「記憶に書いて」と言う。ファイルになったものだけが次に残る
3. 切り上げるとき「NOW.mdを更新して」と言う

### ③ 引き継ぎの確認方法

**新しいセッションを開いて、説明していないのに状況を把握しているかを見てください**と伝える。把握していなければ `@` の2行を疑う。

`scout` サブエージェントはこのプラグインに同梱されているので、インストール済みなら追加の作業は要らない。**フックは自動では登録していない。**塞ぐ対象は会社ごとに違い、こちらの設定をそのまま有効にすると「守られている気がするだけ」の状態になる。必要になったら `ai-ops-add` で、中身をユーザーに合わせてから登録する。

## やらないこと

- ユーザーが答えていないことを推測で書く
- 既存の `CLAUDE.md` や記憶を、確認なしに上書きする
- `feedback_*.md` を作って索引に追加しない
- `CLAUDE.md` に `@memory/...` を書かないまま完了と報告する
- リポジトリを見れば分かること（ファイル構成・コミット履歴・過去の修正）を記憶に書く。二重管理になり、古いほうが先に読まれる
- フックを勝手に登録する
