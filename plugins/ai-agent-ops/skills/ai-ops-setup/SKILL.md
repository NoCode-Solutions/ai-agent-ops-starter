# 土台をつくる

ユーザーの会社の中身は、ファイルでは運べない。**聞き出してから書く。**推測で埋めない。

## 事前の確認

1. リポジトリのルートに `CLAUDE.md` があるか、`memory/` があるかを確認する
2. あれば**上書きしない。**「既にあるので、足りない節を足す形にしますか」と聞き、差分を見せてから進める
3. 無ければ新規作成でよい

## 質問（1問ずつ・まとめて投げない）

前の答えを見てから次を聞く。まとめて5問出すと、答えが浅くなる。

1. この会社（チーム）は何をしているか
2. あなたに任せたい仕事は何か
3. 取り返しのつかない操作を3つ挙げるとしたら何か（送信・公開・削除など）
4. 直近1か月で、私にした同じ説明は何か（2回以上言ったこと）
5. 判断に迷ったとき、進めてよいか、止めて聞くべきか

**3と5は答えが出ないことがある。**空欄のまま進めてよい。空欄は社内でまだ決まっていない箇所なので、「何が決まれば埋まるか」を1行添える。

## 作るもの

| ファイル | 中身 |
|---|---|
| `CLAUDE.md`（ルート） | 節は「起動時に読む順番」「やってはいけないこと」「止まって確認する条件」「完了前のチェックリスト」「用語」の5つ |
| `memory/MEMORY.md` | 1行1件の索引。最初は空でよい |
| `memory/NOW.md` | いまの状況。80行以内という上限をファイル自体に書く |
| `memory/feedback_<内容>.md` | 質問4の答えを1件1ファイルで。各ファイルに「何をするか」「なぜか」「どう適用するか」 |

**「やってはいけないこと」は、行動と、やると何が起きるかを対にした表で書く。**右の列が無い表は、状況が少し変わっただけで例外扱いされる。質問3の答えをそのまま左に入れ、右にユーザーの言葉で理由を書く。

`CLAUDE.md` は200行を超えない。超えたら頻度で切り、特定の作業のときだけ要るものは別ファイルへ出して `@` で読み込む。

節の並びと表の形は `${CLAUDE_PLUGIN_ROOT}/reference/CLAUDE.md` に骨格がある。記憶に何を残し何を残さないかは `${CLAUDE_PLUGIN_ROOT}/reference/memory-writing.md`。

## 終わりに伝えること

作ったファイルの一覧と、明日から何をすればいいかを3行で。次の3つを具体的に言う。

1. いつもどおり仕事を1つ頼む。会社の説明は要らない
2. 直したくなったら「記憶に書いて」と言う。ファイルになったものだけが次に残る
3. 切り上げるとき「NOW.mdを更新して」と言う

`scout` サブエージェントはこのプラグインに同梱されているので、インストール済みなら追加の作業は要らない。**フックは自動では登録していない。**塞ぐ対象は会社ごとに違い、こちらの設定をそのまま有効にすると「守られている気がするだけ」の状態になる。必要になったら `ai-ops-add` で、中身をユーザーに合わせてから登録する。

## やらないこと

- ユーザーが答えていないことを推測で書く
- 既存の `CLAUDE.md` や記憶を、確認なしに上書きする
- リポジトリを見れば分かること（ファイル構成・コミット履歴・過去の修正）を記憶に書く。二重管理になり、古いほうが先に読まれる
- フックを勝手に登録する
