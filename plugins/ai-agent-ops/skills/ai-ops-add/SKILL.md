# 困ってから足す

最初から全部は要らない。**症状が出てから、その項目だけ足す。**使ってもいない仕組みを先に入れると、使われないまま残る。

| 症状 | 足すもの |
|---|---|
| 指示していないのに勝手に進んだ | 止まって確認する条件 |
| 「できました」が当てにならない | 完了前のチェックリスト |
| 調べ物をさせると本題が押し流される | 探索の分業（`scout` を呼ぶ） |
| ルールに書いたのに危ない操作をやろうとする | 実行の直前に仕組みで止めるフック |
| 同じ手順を3回以上説明している | スキル |
| 毎朝、状況を説明し直している | 現在地の自動読み込み |

該当する節だけを実行する。複数まとめて足さない。

## 止まって確認する条件

いま勝手に進んでしまった箇所を、`CLAUDE.md` の「止まって確認する条件」に1行として追加する。**場面の記述にする。**「慎重に進める」のような心構えは条件にならない。既存の行と重複しないか確認してから足す。

条件が10行を超えたら書きすぎ。毎回止まるようになると、止まること自体が形骸化する。

## 完了前のチェックリスト

`CLAUDE.md` の「完了前のチェックリスト」に足す。

- 動くこと・存在することの証拠を出したか（コマンド出力・HTTPステータス・画面）
- 成果物を自分で開いて確かめたか
- 変更前後で同じ入力を流して結果を比べたか（既存の仕組みに触れたとき）

足したら、この一覧を完了前に必ず通すことを `CLAUDE.md` に明記する。全文は `${CLAUDE_PLUGIN_ROOT}/reference/before-done.md`。自動化を書いたとき・外に出すときの追加分が入っている。

**自動化では終了コードだけで成功と判定しない。**エージェントは「この方法が使えないので代わりでいいですか」と質問して正常終了する。二度実行しないための判定は、完了マーカーではなく保存先の実状態で行う。その際、環境・対象ID・件数・更新時刻まで見る。別環境や古いキャッシュを見ていれば実状態でも誤判定する。

## 探索の分業

**`scout` は同梱されているので、作る作業はない。**インストール済みなら「このキーワードが出てくるファイルを全部探して」のように頼めば、そちらへ回る。

うまく回らないときは、依頼の形を変える。「全部」「一覧にして」「どこにあるか」のように、**走査して列挙する作業だと分かる言い方**にする。範囲（どのディレクトリか、何を除くか）を添えるとさらに安定する。

呼ばれたかどうかは、サブエージェントが動いた表示で判断する。呼ばれていなければ、本体がそのまま調べている。それで足りているなら問題ない。

**数回のツール呼び出しで終わる調べ物には使わない。**別のエージェントを立てると、そちらに経緯を説明し直す手間がかかる。委譲して得をするのは、中間出力が大量に出る作業だけ。

`scout` には検索のために `Bash` を渡してある。**「変更しない」は指示であって権限の壁ではない。**壁にしたい場合は `tools` から `Bash` を外す（`${CLAUDE_PLUGIN_ROOT}/agents/scout.md` に注記あり）。

## 実行の直前に仕組みで止める

`${CLAUDE_PLUGIN_ROOT}/hooks/block-outbound.sh` が雛形。**そのまま登録しない。**塞ぐ対象は会社ごとに違う。

1. ユーザーのリポジトリ内（`.claude/hooks/`）へコピーする
2. `CLAUDE.md` の「やってはいけないこと」に挙がっている操作を、塞ぐ対象として書き換える
3. **必ず拒否するテスト用の合言葉**を1つ、塞ぐ対象に加える（例：`BLOCK_ME_TEST` を含むコマンドは常に拒否）
4. `.claude/settings.json` に **Bash の PreToolUse として絶対パスで**登録する。既存の設定がある場合は配列へ追記し、上書きしない。登録後にJSONとして壊れていないか確認する
5. 実行できる状態にする。macOS と Linux は `chmod +x`。**Windows では実行権限の概念が違う**ので、`.claude/settings.json` の `command` 側で何に実行させるかを明示する（Git Bash なら `bash "<絶対パス>"`、PowerShell へ移植したなら `powershell -File "<絶対パス>"`）。どちらの場合も、登録したパスがそのPCの実際のパスになっているかを確認する
6. **合言葉を含む無害なコマンドを1つ打って、拒否されることを確認する。**本物の危険なコマンドは絶対に使わない。フックが効いていなければ、そのまま実行されてしまう

**絶対パスと実行権限のどちらかを忘れると無言で動かない。**エラーも出ないので、効いていると思い込んだまま使い続けることになる。だから6の確認を飛ばさない。

### 塞げる範囲を正しく伝える

Bash の PreToolUse で止まるのは、**シェル経由で実行される操作だけ。**次は止まらないので、ユーザーへ必ず伝える。

- ファイル編集ツール（`Write` / `Edit`）による書き換え
- MCPサーバー経由の操作
- ブラウザ操作ツール
- PowerShell など別のシェル

塞ぎたい経路が他にもあるなら、その経路のツール名で別に設定する。**「全部塞いだ」とは言わない。「設定した経路を塞いだ」と言う。**

このフックは最後の砦であって、判断の代わりではない。塞いでいないパターンは必ず残るので、`CLAUDE.md` の記述を緩めない。取り消せない操作は、フックで止めるより**そもそも実行できない作りにする**ほうが強い（送信の指定を渡すとエラーになるコードにする、追記以外の書き込み方法を持たせない）。

## 手順をスキルにする

いまやった作業を、次から同じ手順で再現できる形にする。置き場所は `.claude/skills/<名前>/SKILL.md`。同名のスキルが既にあれば上書きせず、差分を見せて確認する。

先頭の `description` に3つ入れる。①ユーザーが言いそうな言い回しをそのまま並べる ②対象の範囲 ③使わない場面。本文は「事前の確認」「手順」「やらないこと」の3節。今回踏んだ失敗は「よくある失敗」として残す。

**`description` が本体。**手順を丁寧に書いても、ここが曖昧だと呼ばれない。広すぎると関係ない場面で呼ばれる。使わない場面を書き忘れると、近い話題のたびに出てくる。

作ったら `/skills` で一覧に出ることを確認する。**`.claude/skills/` を今回はじめて作った場合は、Claude Codeの再起動が要る。**

スキルはプロジェクト内にもユーザー全体の設定下にも置ける。両方に同じ名前があると、どちらを直せばよいか分からなくなる。**まず置き場所を1か所に決める。**共有したいならプロジェクト側、自分だけならユーザー側。両方に実体を置かない。

## 現在地の自動読み込み

まず `CLAUDE.md` に `@memory/NOW.md` の記述があるかを確認する。あれば起動時に読まれているので、フックは要らないことが多い。

そのうえで、行数の打ち切りと警告まで欲しい場合は `${CLAUDE_PLUGIN_ROOT}/hooks/inject-now.sh` を使う。`.claude/hooks/` へコピーし、冒頭の `NOW` を実際の絶対パスに書き換え、SessionStart で発火するよう `.claude/settings.json` に絶対パスで登録し、実行権限を付ける。上限は `MAX_LINES=80` で、現在地ファイル自身に書く上限と同じ数にしておく。

登録したら実際に1回動かして出力を見せる。新しいセッションで、説明していないのに状況を把握していれば成功。

行数の上限は、これを毎回読み込ませるためのもの。決めておかないと、終わった案件の記録が積み上がって現在地のファイルが履歴になる。履歴は `memory/project_*.md` へ移す。

## やらないこと

- 症状が出ていない項目を先回りで足す
- フックを、塞ぐ対象を確かめずに登録する
- フックの確認に、本物の危険なコマンドを使う
- 塞げていない経路があるのに「全部塞いだ」と報告する
- 登録したあと、動作を確認せずに完了と言う
