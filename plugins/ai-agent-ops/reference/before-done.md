# 完了前に通す項目

「できました」と言う前に、上から順に確認する。ひとつでも未確認なら完了と呼ばない。

この一覧は、ルールファイルの中に置いても、別ファイルにして `@` で読み込ませてもよい。
毎回考えていると、急いでいるときに抜ける。

## 共通

- [ ] 動くこと・存在することの証拠を出したか（コマンド出力・HTTPステータス・スクリーンショット）
- [ ] 成果物を自分で開いて確かめたか（別のエージェントの報告で代替していないか）
- [ ] 変更前後で同じ入力を流し、結果を比べたか（既存の仕組みに触れたとき）
- [ ] 文面に入れたURLは全件、実在を確認したか
- [ ] 台帳・一覧ファイルを更新したか
- [ ] 現在地のファイルを更新したか
- [ ] 指摘を受けたなら、記憶に理由付きで書いたか

## 自動化を書いたとき

- [ ] 終了コードを成否の根拠にしていないか
- [ ] 二度実行しないための判定を、マーカーではなく保存先の実状態で行っているか
- [ ] 時刻起動から呼ぶものは、環境変数を空にした状態で再現したか
- [ ] 止まったことに気づける形になっているか（制限時間を先に設定したか）

## 外に出すとき

- [ ] 人の承認を得たか
- [ ] 顧客名・金額・認証情報が混ざっていないか
- [ ] 公開ソースに制作メモのコメントが残っていないか

---

**2行目がいちばん効く。** 分業を進めるほど、他のエージェントの完了報告を根拠に
「できました」と言ってしまう場面が増える。報告は証拠ではない。成果物は自分で開く。

この一覧は、事故が起きるたびに1行ずつ増やしていく。増やしすぎると誰も読まなくなるので、
毎回引っかかる項目だけを残し、その回だけの事情は記憶へ書く。
