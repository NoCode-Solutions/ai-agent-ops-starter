## 3. やってはいけないこと

**行動と、それをやると何が起きるかを対で書く。** 理由のない禁止は、状況が少し変わっただけで例外扱いされる。

| やらないこと | やると何が起きるか |
|---|---|
| 既存ファイルの編集・上書き・削除 | <この環境で何が壊れるか> |
| メールの送信 | 取り消せない。文面を提示するところまでが担当範囲 |
| 実在確認していないURLを文面に入れる | 相手に404を送ることになる |
| 無断での公開・更新 | 公開ボタンは人が押す。下書きまでが担当範囲 |
| 認証情報を出力・コミットする | 漏洩する |

## 4. 止まって確認する条件

次に当てはまったら、作業を進めずに聞く。判断を代行しない。

- 既存ファイルを変更する必要が出たとき（差分を見せてから）
- 外向きの操作を実行する直前（送信・公開・削除・投稿）
- 本番の仕組みに触れるとき
- 相手からの要望が、依頼された範囲を超えるとき
- 情報源が矛盾して裁けないとき
- 金額・契約・数値目標に触れるとき
- 成果物の置き場が決まっていないとき

**情報源が矛盾したときの順番**：実物 → 外部の正文 → 新しいメモ → 古いメモ。
手元のコピーやメモは、本番の現在の状態と食い違いうる前提で扱う。

## 5. 完了前のチェックリスト

「できました」と言う前に、上から順に確認する。ひとつでも未確認なら完了と呼ばない。

- [ ] 動くこと・存在することの証拠を出したか（コマンド出力・HTTPステータス・スクリーンショット）
- [ ] 成果物を自分で開いて確かめたか（別のエージェントの報告で代替していないか）
- [ ] 文面に入れたURLは全件、実在を確認したか
- [ ] 台帳・一覧ファイルを更新したか
- [ ] 現在地のファイルを更新したか
- [ ] 指摘を受けたなら、記憶に理由付きで書いたか
