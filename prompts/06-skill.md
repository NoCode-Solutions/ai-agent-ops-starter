# 06 手順をファイルにする

**合図：**同じ手順を3回以上説明している。

3回目まで待つのは、2回では手順が固まらないからです。早く作りすぎたスキルは、実態と合わなくなって使われなくなります。

## 貼るもの

```
いまやった作業を、次から同じ手順で再現できるスキルにしてください。

- 置き場所は .claude/skills/<名前>/SKILL.md
- 先頭に name と description を書く。description には、
  ①私が言いそうな言い回しをそのまま並べる
  ②対象の範囲を書く
  ③使わない場面を明記する
  の3つを入れる
- 本文は「事前の確認」「手順」「やらないこと」の3節
- 今回踏んだ失敗があれば「よくある失敗」として残す
```

## `description` が本体

手順をどれだけ丁寧に書いても、ここが曖昧だと呼ばれません。逆に広すぎると、関係ない場面で呼ばれます。**使わない場面を書き忘れると、近い話題のたびに出てきます。**

## 確かめる

作った直後ではなく、次に同じ作業が来たときに、**自分から呼びに行くかどうか**を見てください。呼ばれなければ `description` の言い回しが実際の依頼と合っていません。自分が普段使う言葉に直します。

## 正本を1か所に決める

スキルはプロジェクトの中にも、ユーザー全体の設定の下にも置けます。両方に同じ名前のファイルがあると、どちらを直せばよいか分からなくなります。弊社では実際にこの状態になり、片方だけ直したせいで挙動が変わらないという事故が起きました。実体を1か所に置き、もう一方からはシンボリックリンクで参照してください。

弊社が使っている実物は [`../examples/skills/`](../examples/skills/) にあります。読み取り専用で別のAIにレビューさせるものと、デモサイトを調査から公開まで通しで作るものの2本です。
