# 05 実行の直前に機械で止める

**合図：**ルールに書いたのに、危ない操作をやろうとする。

文章で頼むかぎり、守られない場合が残ります。取り返しのつかない操作は、実行の直前に機械で拒否します。

## 貼るもの

```
取り返しのつかない操作を、実行の直前に拒否するフックを作ってください。

- 置き場所は .claude/hooks/block-outbound.sh
- Bash の PreToolUse で発火させ、.claude/settings.json に絶対パスで登録する
- CLAUDE.md の「やってはいけないこと」に挙がっている操作を対象にする
- 同じ操作でも経路が複数ある場合（CLI／API／ライブラリ）は全部塞ぐ
- 改行やパイプでつないだコマンドも1行に潰してから判定する
- 拒否したら、理由と「代わりにどうすればよいか」を返す
- 実行権限を付けるところまでやり、動作を1回試してください
```

## 確かめる

**登録が絶対パスになっているか。実行権限が付いているか。**どちらかを忘れると、フックは無言で動きません。エラーも出ないので、効いていると思い込んだまま使い続けることになります。

拒否されるはずのコマンドを1つ実際に打って、止まることを目で確認してください。

## 最後の砦であって、判断の代わりではない

塞いでいないパターンは必ず残ります。フックを入れたからといって、`CLAUDE.md` の記述を緩めないでください。

経路をまとめて塞ぐと、思わぬところで引っかかります。この配布物を作っているときに、フックの雛形そのものへメール送信のパターンを書き込もうとして、**弊社のフックがその書き込みコマンドを拒否しました。**書こうとした文字列が、送信コマンドとして検知されたためです。過剰な反応ですが、そういう形で効きます。

## もう1段強い方法

フックで止めるのではなく、**その操作を実行できない作りにしてしまう方法です。**社内のある担当は「勝手に送信するな」をルールに書かず、送信の指定を渡すとエラーで止まるコードにしています。指示を足すのではなく構造を変える、という考え方です。

動く実装は [`../plugins/ai-agent-ops/hooks/block-outbound.sh`](../plugins/ai-agent-ops/hooks/block-outbound.sh) にあります。
