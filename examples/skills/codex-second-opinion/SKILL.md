# Codex セカンドオピニオン

## 概要

`codex exec`（Codex CLIのヘッドレス実行）で成果物をGPT系モデルに別視点でレビューさせ、指摘をClaude自身の判断と突き合わせて報告する。

## 基本コマンド

```bash
codex exec --skip-git-repo-check -s read-only --color never \
  -C <対象ディレクトリ> \
  -o <一時ディレクトリ>/codex_review.md \
  "<レビュー依頼プロンプト>"
```

- `-s read-only`: 読み取り専用サンドボックス。Codexにファイルを変更させない（必須）
- `--skip-git-repo-check`: gitリポジトリ外でも実行可
- `-o FILE`: 最終回答だけをファイルに保存（実行ログと分離される）
- `-C DIR`: Codexの作業ルート。対象ファイルがあるディレクトリを指定
- 長文をチャットから受けた場合は一時ディレクトリにファイル化し、パスで渡す（引数に全文を埋め込まない）

実行は数分かかることがある。timeoutは300000以上、大きい対象は `run_in_background` を使う。

## 手順

1. 対象を特定する。ファイルならパス、チャット内テキストなら一時ディレクトリに保存
2. レビュー観点をプロンプトに明記する（例: 誤字脱字／論理の飛躍／事実誤認の疑い／ターゲット適合／構成）。依頼者が観点を指定していればそれを最優先
3. プロンプトに「日本語で、指摘は重要度順に、根拠付きで」と回答形式を指定して実行
4. `-o` の出力を読み、**Codexの指摘を鵜呑みにせず**、指摘ごとに「同意（採用推奨）／不同意（理由）／要確認」の判定を付けて報告する

## プロンプト例

```
あなたはレビュアーです。~/path/to/draft.md を読み、
以下の観点で問題点を重要度順に指摘してください。
観点: 事実誤認の疑い、論理の飛躍、ターゲット（中小企業の経営者）とのズレ、冗長な箇所
各指摘に根拠と修正案を付け、日本語で回答してください。
```

## 注意

- `401 Unauthorized` が出たら未ログイン。自分でログインを試みず、ユーザーに `codex login` の実行を依頼する
- クライアント機密を含む成果物はOpenAIに送信される。社外秘の具体名・数値は抽象化してから渡すか、送信前にユーザーに確認する
- Codexへの送信・レビューまでが本スキルの範囲。指摘の反映はユーザーの指示を待つ

## よくある失敗

| 失敗 | 対処 |
|------|------|
| レビュー結果をそのまま転記して終わり | 必ずClaudeの判定（同意/不同意/要確認）を付ける |
| 観点なしで「レビューして」と丸投げ | 観点を明記しないと一般論しか返らない |
| `-s` 指定漏れでファイル変更される | 常に `-s read-only` を付ける |
