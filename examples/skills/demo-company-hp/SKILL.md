# 提案・デモ用コーポレートサイト制作

会社情報リサーチ → 画像生成 → 静的マルチページ → ブラウザ検証 → 別AIによるクロスレビュー → 公開、の再現手順。

## 事前の疎通確認（先にやる）

- **画像生成に使うCLI**: `codex exec --version`。401 や未ログインならユーザーにログインを依頼する（画像生成とレビューが両方止まる）
- **ホスティングCLI**: `npx vercel whoami`。未認証ならユーザーに依頼する
- **作業ディレクトリ**: 先に `<プロジェクト名>/` を作って cd し、以降そこを cwd とする（`research/` `specs/` `site/` を配下に置く）。以降の相対パスと `-C` の基準をここに統一する

## 全体フロー

1. **合意形成** — ①軸（ブランド世界観／事業紹介／両立）②規模（1ページ／マルチページ）③位置づけ（提案デモ／本番）④ビジュアル方針を握る。実在企業なら「提案用イメージ」の明記を前提にする。仕様書＝`specs/`
2. **調査 → 事実台帳** — 公的DB・公式サイト・業界DBで裏取り。`research/company-facts.md` に「確定（出典URL付き）／未確認」で二分する。**未確認は創作せず**、一般表現か「取材のうえ掲載予定」にする
3. **必要画像リストを構成から確定 → 生成**（下記）。枚数・ファイル名・用途は spec の構成が決まってから起こす
4. **静的マルチページ実装** — `site/` に純静的HTML/CSS/軽量JS。共通ヘッダーとフッターは各HTMLに直書きし、CSSはトークン化して1枚に集約する。この工程の成果物に **favicon.svg** と各ページの **og:image**（まず相対、公開後に絶対化）を含める
5. **ブラウザ検証**（下記）
6. **別AIによるクロスレビュー → トリアージ** — 読み取り専用でデザイン／コピー／アクセシビリティ／バグ／レスポンシブを列挙させ、妥当な指摘だけ採用する（過剰対応しない）
7. **公開** — 公開はユーザーの承認を得てから実行する（下記）

## 画像生成（再利用価値が大きい）

生成に2分以上かかることがあり、フォアグラウンドだとタイムアウトする。**バックグラウンドで走らせる。**

```bash
# ログの出力先は mktemp で作る。/tmp に固定名で置くと、
# 同じ端末の別ユーザーから読めてしまい、名前の衝突も起きる。
WORK=$(mktemp -d)
nohup codex exec --sandbox workspace-write --skip-git-repo-check -C "$(pwd)" \
  'image_generation ツールで photorealistic な画像を生成。被写体:… 実写風・イラスト/フラット不可・文字と人物の顔は入れない。生成後 site/assets/img/NAME.png にコピーし ls site/assets/img/ を表示。' \
  > "$WORK/img.log" 2>&1 &
echo "$WORK"
```

`--sandbox workspace-write` は書き込みを許す指定なので、**書き込ませたい場所だけを含むディレクトリで実行する。**リポジトリ全体を作業ルートにしない。

複数枚は1回の実行で順番に生成させ、それぞれのパスへコピーさせると効率がよい。

**完了検知**（待つだけにしない）:

```bash
for i in $(seq 1 20); do
  [ -f site/assets/img/NAME.png ] && { echo ready; break; }
  pgrep -f "codex exec" >/dev/null || { echo "done"; break; }
  sleep 12
done; tail -5 "$WORK/img.log"
```

生成物は `~/.codex/generated_images/<id>/exec-*.png` に出る（`<id>` は毎回変わる）。コピーさせるか、自分で拾う。**必ず中身を目視する**（プロンプトを無視した別内容が出ることがある）。

**圧縮と後始末**: `sips -s format jpeg -s formatOptions 82 --resampleHeightWidthMax 1600 in.png --out out.jpg`（20MB→3〜4MB）→ 全HTMLの `.png` 参照を `.jpg` に置換 → 中間PNGを削除（`grep -rl '\.png' *.html` が0か確認）。

実在企業では「実写でなくAI生成イメージ」である旨をフッターに明記し、本番は実写差し替えを前提にする。

## 検証の勘所（ハマりどころ）

- `file://` はブラウザ操作ツールにブロックされる。ローカルサーバーを立てる。**待ち受けアドレスを明示する**:

  ```bash
  cd site && python3 -m http.server 8756 --bind 127.0.0.1 &
  ```

  `--bind` を省くと全インターフェースに開き、同じネットワークにいる人から制作中のサイトが見える。

- `cleanUrls` 相当の設定はローカルでは効かない。HTMLのリンクは `.html` 付きで書いて検証し、拡張子なしの本番挙動は公開後に確認する
- `.fade-in`（初期 `opacity:0` ＋ IntersectionObserver）はスクロール前だと空白に写る。撮影時は `document.querySelectorAll('.fade-in').forEach(e=>e.classList.add('is-visible'))` してから。**JS無効対策に `<noscript><style>.fade-in{opacity:1;transform:none}</style></noscript>` を必ず入れる**
- `position:sticky` ヘッダーはページ全体の撮影で中間に浮くアーティファクトが出る。実害の判定はスクロール0のビューポート撮影で行う
- モバイルはハンバーガーの切替幅（~860px）とトグルの aria / Esc を確認する。favicon.svg で404を消す

## 先回りで潰すアクセシビリティ・実バグ

- **配色由来のコントラスト事故**: 現在ページの強調色がボタン背景と同色で文字が消える等 → 装飾ルールを `a:not(.btn)` に限定する
- 見出し階層の飛び（h2直下でh4／フッターh5）→ h3等に統一し、CSSで見た目を維持する
- `<li>` は必ず `<ul>` 内。表は `<th scope="row">`
- `og:image` の相対URLはSNSで取得できない → 公開後に絶対URL化する

## 公開

**公開は取り消しにくい操作なので、実行前に人の承認を得る。**

```bash
cd site && npx vercel deploy --prod --yes
```

`--yes` は確認を飛ばす指定で、コマンドを打った瞬間に本番へ出る。承認を得るまで実行しない。
公開URLを取得したら、全HTMLの `og:image` を絶対URLに置換して、もう一度デプロイする。

## やらないこと（デモのスコープ）

CMS連携・多言語・予約・フォームの実送信・地図の実埋め込みは対象外（フォームはダミー、地図はプレースホルダ）。本番採用時のタスクとして仕様書に残す。
